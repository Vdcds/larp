# PR2: Breadth-first and depth-first search

Source: [program](../pr2.txt) and [notebook](../pr2.ipynb). Revision: [PR2 cheat sheet](../CHEATSHEET.md#pr2-bfs-and-dfs).

## Two-minute explainer

This program searches for a route from `A` to `L` in a graph. The graph is a dictionary: each key is a node, and its list contains outgoing neighbors. The program has no edge weights, so a route's length means its number of edges.

Breadth-first search, or BFS, explores shallower routes before deeper routes. Its frontier is a queue created with `deque`. The queue stores whole paths, beginning with `[A]`. `popleft()` removes the oldest path, and `path[-1]` gives the current node. If that node is the goal, BFS returns the path. Otherwise, the program marks an unvisited node and appends a new path for each neighbor.

Depth-first search, or DFS, uses a stack. `pop()` removes the most recently added path, so DFS continues along a branch before returning to alternatives. The code adds neighbors in reverse order. That detail makes the leftmost listed neighbor get explored first, because the last neighbor pushed is the first one popped.

Both functions use a `visited` set to avoid expanding a node repeatedly. The goal check occurs before the expansion check. On the supplied graph, both functions return `A -> B -> F -> J -> L`. The route has five nodes and four edges, so the printed length is four. They find the same route here because the graph has only one route to `L`.

BFS finds a shortest route by edge count in an unweighted graph. DFS does not generally guarantee the shortest route. The difference is the order of exploration, not whether the answer is printed correctly. This implementation copies entire paths into the frontier, which adds storage and copying overhead beyond a textbook node-only traversal.
