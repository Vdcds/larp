## Two-minute explainer

This program searches a weighted graph from `A` to `G`. Each edge stores a neighbor and a travel cost. A separate `heuristic` dictionary estimates the remaining cost from each node to the goal. The algorithms use those estimates to decide which candidate path to explore next.

Greedy best-first search ranks a path only by `h`, the heuristic of its last node. After expanding `A`, it chooses `C`, whose heuristic is four, ahead of `B`, whose heuristic is five. It then reaches `F` and `G`. The returned route is `A -> C -> F -> G`. Its edge costs sum to `4 + 2 + 3 = 9`, although the program does not print this greedy cost.

A* ranks a candidate by `f = g + h`. Here, `g` is the cost already paid along the path, and `h` estimates the cost still needed. The tuple in `open_list` stores `f`, `g`, and the whole path. For every edge, the code adds its cost to `g`, adds the neighbor's heuristic, and inserts the candidate. Sorting the list puts the smallest tuple first.

For this graph, A* returns `A -> B -> D -> G`, with total cost `1 + 2 + 3 = 6`. This shows why looking close to the goal is different from taking a cheap complete route.

The supplied heuristic is consistent: each node's estimate is at most an edge's cost plus the next estimate. That matters because this A* implementation permanently closes expanded nodes. A different, inconsistent heuristic can require reopening nodes when a cheaper path appears. The notebook repeats the display calls, so it can print the results more than once. `greedy_bfs` means greedy best-first search here, not breadth-first search.
