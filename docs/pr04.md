# PR4: Interactive rule-based expert system

Source: [program](../pr4.txt) and [notebook](../pr4.ipynb). Revision: [PR4 cheat sheet](../CHEATSHEET.md#pr4-interactive-rule-based-expert-system).

## Two-minute explainer

This program demonstrates an interactive rule-based expert system. It asks about seven symptoms and collects the ones answered with `yes`. The `knowledge_base` dictionary maps each possible conclusion to the symptoms required by that rule. The rules are hard-coded examples, not a learned medical model.

The input loop visits `fever`, `cough`, `body_pain`, `sneezing`, `runny_nose`, `high_fever`, and `breathing_problem` in that order. It changes underscores to spaces for readable prompts. `.lower()` makes `YES` and `Yes` behave like `yes`. Only the exact resulting string `yes` adds a symptom to the `facts` list. Leading or trailing spaces are not removed, and other answers are skipped without another prompt.

The rule loop checks `all(condition in facts for condition in conditions)`. Every listed condition must be present. For example, `flu` requires fever, cough, and body pain. `infection` requires fever and body pain. If those three symptoms are present and the others are absent, both rules match. The program prints `Possible condition: Flu` and `Possible condition: Infection`.

The `cold` rule needs cough, sneezing, and runny nose. The `doctor_visit` rule directly needs high fever and breathing problem. High fever does not automatically add fever; the code treats them as separate inputs. Each matching conclusion goes into `conclusions`. All seven answers set to `yes` produce all four conclusions. No matching rule produces `No matching condition found.`

The code calls this forward chaining because it reasons from supplied facts toward conclusions. More precisely, it makes one pass of forward rule matching. It never adds conclusions back into `facts`, so it cannot propagate a chain of derived facts. Unlike the earlier repository version, this program has no backward-chaining function. Its printed labels demonstrate rule matching; they do not establish a diagnosis or a probability.
