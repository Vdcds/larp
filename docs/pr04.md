# PR4: Forward and backward chaining

Source: [program](../pr4.txt) and [notebook](../pr4.ipynb). Revision: [PR4 cheat sheet](../CHEATSHEET.md#pr4-forward-and-backward-chaining).

## Two-minute explainer

This program demonstrates a small rule-based expert system. It starts with three true facts: `fever`, `cough`, and `cold`. A rule maps a conclusion to the conditions needed to support it. For example, `flu` requires both `fever` and `cough`, and `doctor_visit` requires `flu`.

Forward chaining begins with the known facts and asks what else follows. The function copies the facts into `inferred`. It scans every rule and uses `all(...)` to check whether every condition is true. When a new conclusion becomes true, it adds that conclusion and records that progress occurred. The loop repeats until a complete scan adds nothing.

With these inputs, forward chaining derives `flu`, `infection`, and `doctor_visit`, in addition to the original facts. A later rule can use a fact added earlier in the same scan. Repeating the scan still matters because another rule order might require another pass. Since the code only adds true facts from a finite rule dictionary, forward chaining eventually stops.

Backward chaining starts with a particular goal. For `doctor_visit`, it asks whether `flu` can be proved. That leads to two smaller questions: is `fever` true, and is `cough` true? Both are initial facts, so the goal returns `True`. A goal already present as a true fact succeeds immediately. A goal with no fact and no supporting rule fails.

Forward chaining is data-driven and can derive many conclusions. Backward chaining is goal-driven and investigates the conditions for one requested conclusion. This example uses AND conditions and one rule per conclusion. The backward function has no cycle detection, so circular rules can recurse forever. These symptom names are toy facts for an inference exercise, not a diagnostic model.
