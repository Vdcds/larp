# PR11: Model comparison and hyperparameter tuning

Source: [program](../pr11.txt) and [notebook](../pr11.ipynb). Revision: [PR11 cheat sheet](../CHEATSHEET.md#pr11-model-optimization).

## Two-minute explainer

This program compares SVM, Random Forest, and AdaBoost on the Breast Cancer dataset. It first makes a stratified 80/20 train/test split. The labels are zero for malignant and one for benign. All models use the same split, so their test predictions refer to the same examples.

SVM learns a separating decision boundary. Its pipeline includes `StandardScaler` because feature scales affect the boundary and kernel calculations. Random Forest combines decision trees trained with randomness and aggregates their predictions. AdaBoost builds weak classifiers in sequence and gives more attention to difficult training examples. These are different ways to fit a classifier, not three names for the same algorithm.

The first loop trains the baseline models and prints test accuracy and classification reports. Another loop performs five-fold cross-validation on the training subset. Each fold takes a turn as validation data, while the other folds supply training data. The average validation accuracy gives a broader view than one split alone.

`GridSearchCV` then tries specified hyperparameters. SVM searches `C` and kernel type. Random Forest searches the number of trees and maximum depth. AdaBoost searches the number of estimators and learning rate. The `model__` prefix targets SVM settings inside its pipeline. Scaling therefore fits within each training fold instead of learning from validation rows.

`best_score_` is the best mean cross-validation score, not a test score. With the default refit behavior, `best_estimator_` is already fitted on the entire training subset using the chosen settings. The final loop evaluates those fitted models on the held-out test data, and a chart compares baseline and tuned accuracies.

Tuning does not guarantee a higher test score. In a careful evaluation, model choices come from training cross-validation, and the test set is reserved for a final check. Repeatedly choosing settings from the printed test results would make that test estimate less trustworthy.
